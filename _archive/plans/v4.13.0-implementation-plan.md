### 0.2 — Update `lcars-color-utils.js` — STATE_COLOR_MAP + CO₂ Reconciliation

**File**: `custom_components/lcars_dashboard/js/src/lcars-color-utils.js`  
**Spec References**:
- LCARS-AIR-PURIFIER-VERIFICATION-SPEC.md §v4.13.0 Enhancement 2 (CO₂ 3-tier)
- LCARS-V413-VISUAL-ENHANCEMENTS-BRIEF.md §Cross-Spec DRY Recovery (STATE_COLOR_MAP)
- LCARS-TEMP-HUMIDITY-GRID-SPEC.md §5 (getTempColor, getHumidityColor)

**Changes**:
1. **Reconcile `getCo2Color()`** to 3-tier model:
   - ≤ 800 ppm → `var(--lcars-ice)` (nominal)
   - 801–1200 ppm → `var(--lcars-sunflower)` (elevated)
   - > 1200 ppm → `var(--lcars-tomato)` (high)
   - Bad data → `var(--lcars-tomato)` (alert on invalid — Worf R1)

2. **Add `STATE_COLOR_MAP`** — consolidated lookup for 8 state→color functions:
   - `getAlarmStateColor(state)`
   - `getHvacActionColor(action)`
   - `getMediaStateColor(state)`
   - `getPoolHeatingColor(action)`
   - `getWeatherConditionColor(condition)`
   - `getIrrigationZoneColor(state)`
   - `getComfortColor(comfortClass)` — whitelist: `COMFORT_COLORS` object (Worf R1)
   - `getCo2Color(ppm)` — reconciled 3-tier

3. **Add temp/humidity color helpers** from Temp Grid spec §5–6:
   - `getTempColor(tempF)` — cold/cool/nominal/warm/hot
   - `getHumidityColor(humidity)` — dry/nominal/humid
   - `getTempComfortClass(tempF)` — returns class name string for CSS

**Acceptance Criteria**:
- [ ] `getCo2Color()` returns 3 tiers only (ice/sunflower/tomato) — 4-tier model removed
- [ ] All color resolver functions use `Number()` + `Number.isFinite()` guard on input
- [ ] `COMFORT_COLORS` whitelist prevents raw entity data from reaching `style.setProperty()`
- [ ] Existing atmoscrubber CO₂ coloring still works after reconciliation
- [ ] All new functions exported and available to panel renderers

**Reviewer**: Data (architecture), Worf (input validation)

### 1.3 — Header Numeric Code Watermark

**Spec**: Device Panel §7.8, Creative Brief §1.3  
**Target**: Panel header area, right-aligned  
**Security**: Worf M3 — must use `<span aria-hidden="true">`, NOT CSS `content:attr()`

**Implementation**:
- Generate deterministic 6-digit code from entity ID: `hashCode(entityId) % 1000000` (Data L-4)
- Format as `XXX-XXXXX` (3-5 split with dash)
- Render as `html\`<span class="panel-numeric-code" aria-hidden="true">${code}</span>\``
- Style: `font-size: 0.625rem; opacity: 0.4; color: var(--lcars-gray); position: absolute; right: var(--lcars-gap)`
- **NOT** `data-code` attribute + `content: attr(data-code)` — Worf prohibits CSS content for data

**Acceptance Criteria**:
- [ ] Every panel shows a unique 6-digit code in the header
- [ ] Code is deterministic (same entity always produces same code)
- [ ] Code is hidden from screen readers (`aria-hidden="true"`)
- [ ] Code never contains entity data — only a numeric hash

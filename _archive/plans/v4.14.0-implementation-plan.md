#### Story 2.1: Grid Card Core — Discovery, Rendering, Hass Setter

**As a** SwitchBot Meter owner, **I want** a single card that discovers all my temperature/humidity sensors, groups them by floor, and displays a tile grid, **so that** I can monitor whole-home environmental conditions at a glance.

**Conditions addressed**: W-R1, D-C1, D-C3

**Files created**:
- `src/lcars-internal-sensors-grid.js`

**Imports from existing code** (no duplication):
- `lcars-color-utils.js`: `getTempColor`, `getHumidityColor`, `getTempComfortClass`, `getSafeComfortColor`, `COMFORT_COLORS`
- `lcars-sparkline.js`: `renderSparkline`, `fetchSparklineData`

**Implementation**:

##### §Entity Discovery — D-C1 Compliance (NO WebSocket)

The spec's `discoverSensorGroups()` uses four `hass.callWS()` registry calls. **This is prohibited by D-C1.** Instead, use the `hass` object's already-loaded properties:

```javascript
// D-C1: Use hass object properties — NO WebSocket calls for discovery
const entities = Object.values(this._hass.entities);   // entity registry
const devices  = Object.values(this._hass.devices);    // device registry
const areas    = Object.values(this._hass.areas);       // area registry
const floors   = Object.values(this._hass.floors || {}); // floor registry (HA 2024.2+)
```

These are already loaded and reactive on the `hass` object. Zero additional network calls.

##### §Entity ID Validation — W-R1 Compliance

All entity IDs extracted during discovery MUST be validated before use:

```javascript
const ENTITY_ID_RE = /^[a-z_]+\.[a-z0-9_]+$/;

// At extraction time, validate every entity ID
const temperatureEntityId = tempEntity.entity_id;
if (!ENTITY_ID_RE.test(temperatureEntityId)) continue; // skip invalid
```

This validation occurs at extraction time (in the discovery loop), not at render time. Invalid IDs never enter the data model.

##### §Hass Setter — D-C3 Compliance (Tracked Entity Diffing)

The grid card monitors 14+ entities. Without diffing, every `hass` update (100+/minute) triggers a re-render. Implement tracked-entity diffing:

```javascript
set hass(hass) {
  const oldHass = this._hass;
  this._hass = hass;

  // On first set or config change, run discovery
  if (!oldHass || this._needsDiscovery) {
    this._discoverSensors();
    this._needsDiscovery = false;
  }

  // D-C3: Only re-render if tracked entity states actually changed
  if (oldHass && this._trackedEntityIds) {
    let changed = false;
    for (const eid of this._trackedEntityIds) {
      if (oldHass.states[eid] !== hass.states[eid]) {
        changed = true;
        break;
      }
    }
    if (!changed) return; // skip render — no tracked state change
  }

  this.requestUpdate();
}
```

`_trackedEntityIds` is a `Set<string>` populated during discovery with all temperature, humidity, and battery entity IDs. This reduces renders from 100+/min to only when actual sensor values change (~1/min per sensor).

##### §Card Registration

```javascript
if (!customElements.get('lcars-internal-sensors-grid')) {
  customElements.define('lcars-internal-sensors-grid', LcarsInternalSensorsGrid);
}

window.customCards = window.customCards || [];
window.customCards.push({
  type: 'lcars-internal-sensors-grid',
  name: 'LCARS Internal Sensors Grid',
  description: 'Ship-wide environmental monitoring grid',
  preview: true,
});
```

##### §Config Validation

```javascript
setConfig(config) {
  const clampTemp = (v, d) => Math.max(-50, Math.min(200, v ?? d));
  const clampPct  = (v, d) => Math.max(0, Math.min(100, v ?? d));

  this.config = {
    ...config,
    temp_comfort_min:    clampTemp(config.temp_comfort_min, 68),
    temp_comfort_max:    clampTemp(config.temp_comfort_max, 76),
    humidity_comfort_min: clampPct(config.humidity_comfort_min, 30),
    humidity_comfort_max: clampPct(config.humidity_comfort_max, 60),
    battery_alert:       clampPct(config.battery_alert, 20),
    show_sparklines:     config.show_sparklines !== false,
    show_averages:       config.show_averages !== false,
    show_appliance_meters: config.show_appliance_meters === true,
    group_by_floor:      config.group_by_floor !== false,
  };
}
```

##### §Core Render

Render method produces:
1. Header row (title + stardate)
2. Floor-grouped tile grid (auto-fill responsive columns)
3. Summary row (averages + sensor count + low battery count)

Each tile renders: room name, temperature (colored via `getTempColor()`), humidity (colored via `getHumidityColor()`), optional battery badge (pulsing dot if ≤ threshold), optional sparkline, unavailable overlay.

Comfort class on each tile set via `getTempComfortClass()` — drives border color and glow.

Tile tap fires `hass-more-info` event for the temperature entity.

**Acceptance criteria**:
- [ ] Card discovers SwitchBot Meter devices from `hass.entities` / `hass.devices` / `hass.areas` / `hass.floors` — **no `callWS` for registry data**
- [ ] All entity IDs validated with `ENTITY_ID_RE` at extraction time
- [ ] Hass setter diffs tracked entities — `requestUpdate()` only fires when a tracked entity's state object changes
- [ ] Tiles render with correct temperature color, humidity color, and comfort class
- [ ] Appliance meters (fridge/freezer) excluded by default
- [ ] Floor grouping with correct sort order (highest floor first)
- [ ] Empty state renders when no sensors found
- [ ] Unavailable sensors show OFFLINE overlay and are excluded from averages
- [ ] Tile tap opens `hass-more-info` dialog

**Review gate**: Data (architecture — D-C1/D-C3 compliance), Worf (security — W-R1 entity validation)

#### Story 2.2: Sparkline Integration

**As a** dashboard user, **I want** each sensor tile to show a 24-hour temperature trend sparkline, **so that** I can spot trends without opening individual entity histories.

**Conditions addressed**: W-R2

**Files modified**:
- `src/lcars-internal-sensors-grid.js` (created in Story 2.1)

**Implementation**:

1. Import `fetchSparklineData` and `renderSparkline` from `lcars-sparkline.js`.

2. Use `fetchSparklineData()` with the grid card's own cache (`_gridHistoryCache = new Map()`):
   - `cacheKey`: `'sensors-grid'` (single batch for all sensors)
   - `entityIds`: all temperature entity IDs from discovered groups
   - `maxEntities`: 14 (matches Admiral's 14-sensor fleet)
   - TTL: 5 minutes (default)

3. Call `renderSparkline()` per tile with `{ width: 100, height: 16 }` per spec.

4. **W-R2 Compliance**: `fetchSparklineData()` uses `hass.callWS({ type: 'recorder/statistics_during_period' })` — WebSocket only. The spec's `fetchSensorHistory()` (which uses `hass.callApi('GET', ...)` — REST) must NOT appear anywhere in this file.

5. Sparkline fetch is async — triggers on first render, then every 5 min via cache TTL. On fresh data, calls `requestUpdate()` to re-render with sparklines.

6. Sparklines hidden on viewports < 768px (CSS media query).

**Acceptance criteria**:
- [ ] Each tile shows a 24-hour temperature sparkline when `show_sparklines: true`
- [ ] Sparklines use `renderSparkline()` from `lcars-sparkline.js` with `{ width: 100, height: 16 }`
- [ ] Sparkline data fetched via WebSocket (`recorder/statistics_during_period`) — **zero REST API calls**
- [ ] `fetchSensorHistory` / `callApi` does NOT appear in the file
- [ ] Sparkline data cached with 5-minute TTL
- [ ] Sparklines hidden on mobile (< 768px)
- [ ] Tiles with unavailable sensors show no sparkline

**Review gate**: Worf (security — W-R2 WebSocket-only verification)

**Estimated effort**: 2 points (S)

The spec defines `.sensor-tile.humidity-warn` which applies `border-right-color: var(--lcars-sunflower)`. Geordi's condition: temperature-only border — humidity does not drive border color. **Do not include `.humidity-warn` in the CSS.** Humidity is encoded via text color only (per WCAG 1.4.1 — avoid conflicting dual-encoding on border).

##### §Accessibility — G-F3: Keyboard Navigation on Tiles

Each tile gets:
- `tabindex="0"` — focusable via keyboard
- `@keydown` handler — Enter/Space opens `hass-more-info`
- `:focus-visible` styles — visible focus ring

```html
<div class="sensor-tile ${comfortClass}"
     tabindex="0"
     role="listitem"
     aria-label="${areaName}: ${temp} degrees, ${humidity} percent humidity"
     @click=${(e) => this._handleTileTap(e, temperatureEntityId)}
     @keydown=${(e) => { if (e.key === 'Enter' || e.key === ' ') { e.preventDefault(); this._handleTileTap(e, temperatureEntityId); } }}>
```

```css
.sensor-tile:focus-visible {
  outline: 2px solid var(--lcars-sunflower);
  outline-offset: 2px;
}
```

# v4.19.0 Implementation Plan — File I/O Hardening

**Status**: COMPLETE — shipped v4.19.0
**Date**: 2026-04-17
**Backlog item**: 4X-28

---

## Scope

Migrate all 44 raw `async_add_executor_job(open, ...)` calls in `__init__.py` to the existing `_read_yaml_file` / `_write_yaml_file` helpers. Eliminate blocking filesystem calls from the event loop. Fix pre-existing `sortType` validation gap.

## Pre-Implementation Reviews

### Data's Architecture Audit (Phase 2)
- Cataloged all 44 `open()` call sites across 4 groups:
  - **Group A**: 18 config YAML reads → `_read_yaml_file` (direct drop-in)
  - **Group B**: 17 config YAML writes → `_write_yaml_file` (direct drop-in)
  - **Group C**: 6 card YAML writes with JSON round-trip → `_write_yaml_file` (drop redundant `yaml.safe_load(json.dumps(...))`)
  - **Group D**: 3 blueprint YAML writes → `_write_yaml_file`
- No new helpers needed — existing two cover all patterns
- Estimated ~200 lines net reduction

### Worf's Security Review (Phase 2)
- **APPROVED with 5 conditions:**
  1. Migrate `more_pages` read in `websocket_get_configuration`
  2. Migrate blueprint reads in `websocket_get_blueprints`
  3. Eliminate blocking `os.path.exists`/`os.makedirs` in `ws_handle_install_blueprint`
  4. Wrap blocking `os.remove` in delete/remove handlers with executor
  5. Fix `ws_handle_sort_entity` `sortType` validation: `str` → `vol.In(ALLOWED_SORT_TYPES)`
- All 5 conditions met in implementation.

## Implementation

### Migration approach
1. Replaced all Group A reads with `_read_yaml_file(hass, rel_path)` — removed `os.path.exists` guards, `st_size` checks
2. Replaced all Group B writes with `_write_yaml_file(hass, rel_path, data)` — removed `os.makedirs` guards
3. Replaced Group C card writes — dropped `yaml.safe_load(json.dumps(...))` no-op, wrapped in `def _write_card()` executor closures for variable paths
4. Replaced Group D blueprint writes with `_write_yaml_file`
5. Wrapped 5 `os.remove` calls in executor lambdas
6. Wrapped 4 `os.path.isdir` calls in `async_add_executor_job`
7. Fixed `sortType` validation

### Code Review Findings (Phase 6 — 3 rounds)

**Round 1 (Data): REJECT**
- All 7 inline closures were `async def` instead of `def` — executor calls coroutines that are never awaited. Showstopper: card writes and deletes silently do nothing.
- 4 blocking `os.path.isdir` calls in `_load_card_dir_nested/flat` not wrapped
- Dead `nonlocal filename` in `ws_handle_add_card`

**Round 2 (Data): REJECT**
- `_load_card_dir_flat` still had bare `os.path.isdir(full)`
- `nonlocal filename` was actually NEEDED (assignment on line 1163 makes it local) — removal caused `UnboundLocalError`

**Round 3 (Data): APPROVE**
- All issues resolved

**Worf: APPROVE** — all 5 security conditions verified

## Result
- **Net: -200 lines** (324 deleted, 145 added)
- Zero raw `open()` calls remaining
- Zero blocking filesystem calls on event loop
- `sortType` injection vector closed

## Lessons Learned
- `async def` vs `def` in executor closures is a critical distinction — coroutines returned by `async def` are never awaited by `run_in_executor`
- `nonlocal` is required when a closure rebinds a variable that it also reads before the rebinding line
- 3-round review process works — Data caught a showstopper that would have broken card editing for all users

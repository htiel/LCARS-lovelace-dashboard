# v5.7.0-beta.1 — Live Visual Audit (Worf + Geordi review)

**Source:** 46 screenshots in [screenshots/v5.7.0-beta.1/](../screenshots/v5.7.0-beta.1/) captured live against HA at `https://ha.mariner.example/` after release publish.

**Methodology:** All 9 dashboards (top + bottom), 9 navbar click tests, all 20 Habitat sidebar rooms walked. Two post-release hard-refresh re-captures (`50-medical`, `51-cetacean`) confirm the version-string staleness was a browser cache, not a code regression.

## Findings

### A. Orphaned LCARS frame artifacts (matches Captain's attached snippet)

Multiple panels render full-width LCARS frames with only ¼–½ of the row populated, leaving large orange/dark dead zones at the right. The pattern: `ILLUMINATION CONTROL` row header sweeps the full content width, but the dimmer-card column track stops after 1–3 cards, leaving the right portion as an empty orange frame.

| Surface | Capture | Detail |
| --- | --- | --- |
| Habitat → Front Yard | [22-habitat-front-yard.png](../screenshots/v5.7.0-beta.1/22-habitat-front-yard.png) | ILLUMINATION CONTROL row: 2 dimmers populated, right ⅔ empty orange |
| Habitat → Back Yard | [31-habitat-back-yard.png](../screenshots/v5.7.0-beta.1/31-habitat-back-yard.png) | ILLUMINATION CONTROL: 3 dimmers + 1 pill in a 4-col grid; right column orphan |
| Habitat → Office | [36-habitat-office.png](../screenshots/v5.7.0-beta.1/36-habitat-office.png) | ILLUMINATION CONTROL row 1: 3 dimmers + orphan "BED PLUG BOT…" pill in oversized right slot |
| Habitat → Master Bedroom | [30-habitat-master-bedroom.png](../screenshots/v5.7.0-beta.1/30-habitat-master-bedroom.png) | ILLUMINATION CONTROL: 1 dimmer (MY LAMP), right ¾ empty orange |
| Habitat → Deck 1 (Front Yard subsection) | [21-habitat-deck-1.png](../screenshots/v5.7.0-beta.1/21-habitat-deck-1.png) | Same ILLUMINATION CONTROL right-side void |
| Habitat → Kitchen | [27-habitat-kitchen.png](../screenshots/v5.7.0-beta.1/27-habitat-kitchen.png) | Single dimmer card → entire content area below is black void (single-card areas don't backfill or collapse) |

**Likely cause:** `.lcars-illumination-control` container uses `display: grid; grid-template-columns: repeat(auto-fit, minmax(...))` but the parent row sets a fixed full width without `justify-items: start` / `grid-auto-flow: dense`. When entity count < grid track count, the row container still paints the right portion in the LCARS frame colour.

**Recommendation (Geordi):** clamp the illumination row container to the populated columns (use `grid-template-columns: repeat(auto-fill, minmax(min(280px, 100%), 1fr))` with a max-column constraint, OR have the layout drop the frame border on empty tail tracks).

**Issue refs:** likely manifests as part of #196 (auto-fit/auto-fill conversion shipped only on starship-card so far) and #167 (orphaned plug). **NEW BUG** — open as `5X-orphan-illumination-row`.

### C. Dev-prefix entity filter regression (#182 incomplete)

[36-habitat-office.png](../screenshots/v5.7.0-beta.1/36-habitat-office.png) shows 8 entities `PROTOTYPE BUTTON 1` … `PROTOTYPE BUTTON 8` (all OFFLINE) under LIGHTING CONTROL BUTTONS. These should have been filtered by `DEV_PREFIX_RE = /^(?:prototype|debug|test)_/i` in `lcars-entity-query.js`.

**Root cause:** The regex matches on `entity_id` prefix (`prototype_button_1`), but the real entity_ids are likely `binary_sensor.office_prototype_button_*` — area-prefixed, so the regex doesn't bite. Captain's domain prefix isn't first.

**Fix:** change the test to scan the unprefixed local portion of the entity_id (`local = entity_id.split('.')[1].split('_').includes('prototype' | 'debug' | 'test')`) OR check `friendly_name` for matching substring.

**Issue ref:** **#182 — reopen / new dependent**.

## Mission

Close every currently open 4.x backlog item in one release plan while minimizing execution passes, plus add new panel support for EV chargers, portable air conditioners, and HomeKit air purifiers. The controlling principle is file affinity first, then logical coupling, then release risk. The result is ten work batches instead of fifteen isolated stories:

- Batch A consolidates the original formatter and label fixes into one shared display-normalization pass because all three issues ride the same render-value and render-label pipeline.
- Batch B keeps offline degraded-state work together because both items change how unavailable data is colored and surfaced to the user.
- Batch C keeps routing and entity-claim logic together because both items depend on classifier behavior and device-level grouping.
- Batches D, E, F, and G stay separate because they touch isolated control paths with little file overlap.

This release should finish the remaining 4.x cleanup before any new 5.x scope expansion. The bugs ship first. The panel-order feature ships after the existing surfaces are stable. The HACS metadata fix stays last because it is operationally isolated and should not distract from functional validation.

### Batch A: Shared Display Normalization

Items:

- 4X-47 - Battery telemetry raw decimals
- 4X-48 - Life Support header badge raw temperature
- 4X-49 - Environment sparkline labels show device_class names

Why this is one batch:

- All three issues are presentation defects caused by bypassing existing shared helpers.
- The source-of-truth helpers already exist in `lcars-format-utils.js`: `formatNumber()` at line 49 and `canonicalLabel()` at line 112.
- The implementation work is not new logic; it is rerouting live render surfaces back through the shared formatter/label pipeline.

Files to modify:

- `custom_components/lcars_dashboard/js/src/panels/battery/lcars-battery-panel.js`
- `custom_components/lcars_dashboard/js/src/panels/lifesupport/lcars-lifesupport-panel.js`

- `custom_components/lcars_dashboard/js/src/lcars-format-utils.js` only if a narrow helper extraction is needed to avoid duplicating formatting glue

Specific changes:

1. 4X-47 - battery numeric formatting
   - In `lcars-battery-panel.js`, import `formatNumber()` and route all direct numeric string interpolation through it.
   - The current extracted battery panel still renders raw values in `renderContent()` instead of using the shared formatter:
     - total-in and total-out rows near lines 327-345 interpolate `totalIn.state.state` and `totalOut.state.state` directly.
     - telemetry and diagnostics sensor rows near lines 346-381 append `state.state` and `unit` directly.
     - number slider value chips near lines 396-442 and 458-506 render raw `val`.
   - The target behavior is the same normalization already present in the old homepage-card battery path at lines 4929 and 4987.

2. 4X-48 - Life Support badge formatting
   - In `lcars-lifesupport-panel.js`, update `renderBadge()` at line 216 so the temperature value path uses `formatNumber(String(tempVal), 'temperature')` instead of raw numeric output.
   - Keep the current ambient selection logic intact. Only the badge display string changes.

3. 4X-49 - canonical sparkline labels
   - In `lcars-environment-panel.js`, replace `_friendlyName(state, entity)` with `canonicalLabel(dc, rawFallback, entityId)` in the sparkline tray mapping inside `renderContent()` near lines 221-230.
   - In `lcars-homepage-card.js`, mirror the same fix in the legacy environment sparkline rendering path around lines 4729-4738 so extracted and fallback surfaces do not drift.
   - Do not change Life Support sparkline tray logic. It already uses `canonicalLabel()` correctly in `lcars-lifesupport-panel.js` at line 516.

Acceptance criteria:

- UPS Air, River 3+, and BIGBOY-DPU battery telemetry no longer expose raw decimal precision in the extracted battery panel.
- Life Support header badge rounds temperature values using the same formatter rules as the rest of the UI.
- Environment sparkline labels use canonical short labels such as `PM2.5`, `CO2`, `VOC`, `TEMP`, and `RH` instead of raw Home Assistant device_class strings.

- M

## Risks And Mitigations

| Risk | Probability | Impact | Mitigation |
|---|---|---|---|
| Shared offline color normalization accidentally flattens meaningful alert semantics | Medium | High | Restrict the `getStateColor()` change to unavailable and unknown degraded states only; do not touch live alarm or hazard mappings |
| Alarm sibling absorption over-claims devices that legitimately belong to more than one panel | Medium | High | Make the second sweep device-aware and only absorb siblings after a zone entity from that same device has already been claimed |
| BlueAir workaround broadens battery-class exceptions too far | Medium | Medium | Detect filter life by entity id pattern plus purifier context, not by `device_class: battery` alone |
| Media standby compaction hides controls users still need for active playback | Medium | Medium | Gate the compact branch strictly to idle and standby states; leave playing and paused unchanged |
| Panel-order persistence drifts from live area composition | High | Medium | Apply override order as an overlay on `PANEL_TYPE_ORDER`, prune stale types on read, and append newly discovered panel types using default order |
| EV charger classifier claims non-EV power entities | Medium | High | Detection heuristic must require `wallbox` platform OR explicit EV naming patterns; do not match generic power sensors |
| HomeKit purifier sibling heuristic too broad | Medium | Medium | Require PM2.5 or AQ sensor on same device; generic HomeKit fans rejected without AQ sibling |
| Portable AC aux controls overcrowd climate panel | Low | Medium | Aux switches render in a dedicated group below climate-native controls; timer is compact stepper |
| HACS icon fix consumes time without a verified root cause | Low | Low | Keep Batch G metadata-only unless asset validation proves an actual file problem |

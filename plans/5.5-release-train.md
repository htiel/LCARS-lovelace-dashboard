# LCARS Dashboard — 5.5.x Release Train Implementation Plan (Amended)

**Branch:** `5.0` (default, stable)
**Current shipping version:** v5.4.6
**Plan authored:** 2026-05-10
**Amended:** 2026-05-10 (post 5-agent review: Data/Geordi/Worf/Wesley/Riker recommendations applied)
**Total open issues at plan time:** 121 (90 new from review batch #125–#214 + 31 existing)

## Mission

Address the entire remaining 5.x backlog through a disciplined patch train. Each release is theme-coherent, single-file-disciplined (<460 changed lines per file per release), and touches each large card file at most **once** across the train. No file is opened twice.

**Amendment note:** The original plan placed a global `*-layout.js` aria-label sweep in 5.5.1, which would have reopened every layout file later in the train. The sweep is now distributed into each owning dashboard release. 5.5.1 retains only true cross-cutting shell work.

## Operating constraints

- All work targets branch `5.0`. Never push to deleted `4.0` (archived as `archive/4.0-final`).
- Each release: bump `const.py` VERSION, `manifest.json` version, `js/package.json` version (the 3-file version sync rule).
- Each release: `git commit` → `git push origin 5.0` → `gh release create 5.5.x --target 5.0 ...` (HACS requires releases to detect updates).
- No betas needed — 5.x is stable.
- Single-file diff ceiling: 460 lines per file per release.
- Total commit ceiling: 9000 lines per release.
- Run `npm run build` before each commit; check `lcars-dashboard.js` bundle delta and report it.

## Definition of Done (every release)

**Domain sign-offs (per Riker):** every release requires sign-off from the assigned reviewer(s). When a release touches a domain surface, the corresponding agent **must** be a named reviewer:

- **Security surface** (token/privacy/service-call/auth/code-required) → Worf sign-off.
- **A11y / LCARS visual / keyboard / screen-reader / touch-target** → Geordi sign-off.
- **Perf / memoization / cache / observer / classifier** → Data sign-off.
- **Integration breadth / HA platform diversity** → Wesley sign-off.

**Required steps:**

1. All listed issues closed via commit message `Closes #N, #M, #O` or `gh issue close N -c "Shipped in v5.5.x"`.
2. CHANGELOG.md updated with bug-fix list grouped by dashboard.
3. Three version files updated and matched (`const.py`, `manifest.json`, `js/package.json`).
4. `npm run build` clean; bundle delta noted and within ceiling (≤+5 KiB gzipped/release without written justification).
5. **Train-wide security gates (Worf, per consensus):**
   - `npm audit` zero high/critical.
   - `npm audit signatures` clean.
   - No new `unsafeHTML` / `innerHTML` / `eval` / `new Function`.
   - No new hardcoded secrets, tokens, or URLs with auth params.
   - No new static-path registrations outside `js/dist/`.
   - No new WS handler without voluptuous schema + admin check (where applicable).
   - No new YAML `!include` path without `realpath()` prefix validation.
   - No PHI / secrets in logs or WS error responses.
6. **Executable validation per release** (per Riker): one focused validation that exercises the release's primary change — not just smoke. E.g. 5.5.0: HA restart + create_notification; 5.5.1: keyboard pass on popup; 5.5.2: camera-spec §5 verification; 5.5.3: classifier fixtures pass; etc.
7. **Baseline deltas reported** vs the 5.5.0 baseline (bundle size, startup, first-paint, FPS where relevant).
8. **Rollback criterion documented:** the one observable regression that would trigger a revert + follow-up.
9. Single-file diff <460 lines verified.
10. GitHub release created: `gh release create 5.5.x --target 5.0 --title "v5.5.x — Theme" --notes ...`.
11. Manual smoke test in Captain's HA instance (HACS update → restart → exercise affected dashboards).
12. **Integration-platforms-tested line** in release notes (Wesley ride-along): e.g. `Tested: ESPHome ✓, Tasmota ✓, Z-Wave JS ✓, UNIFI ✓`.

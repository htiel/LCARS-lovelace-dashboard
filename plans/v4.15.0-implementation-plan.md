## 1. Phase 2 Condition Reconciliation

### 1.1 Blocking Conditions — Resolved

| Condition | Issue | Decision | Rationale |
|-----------|-------|----------|-----------|
| **C-4** | Sparkline batch size: spec says 50, Wesley's code says 10 | **20 per batch** | 43 circuits = 3 batches (20+20+3) with 100ms stagger. Balances WS pressure vs. latency. Existing `fetchSparklineData()` accepts `maxEntities` option — pass 20. |
| **C-5** | Per-tile popovers create ~430 extra DOM nodes (43 tiles × ~10 nodes each) | **Singleton popover** | 1 shared `<div popover>` at panel level. On tile click, populate imperatively via `_showCircuitPopover(circuit, sparklineData)` then call `popoverEl.showPopover()`. Reduces DOM from ~430 to ~10 nodes. |
| **C-6** | `_partitionPowerEntities()` referenced but never defined | **Defined in Wesley addendum appendix** | Partitions entries into `{ switches, powerSensors, energySensors, voltageSensors, currentSensors, diagnostics }`. Same pattern as `_partitionBatteryEntities()`. Implementation in Story 3. |

### 1.2 Naming Standardization — Resolved

| Condition | Before | After | Rationale |
|-----------|--------|-------|-----------|
| **F-1** | `getPowerDrawColor(watts)` | `getPowerColor(watts, thresholds = {})` | Matches project convention (`getTempColor`, `getHumidityColor`). Wesley's threshold-aware signature adopted. |
| **F-2** | `getPowerDrawLabel(watts)` | `getPowerLabel(watts, thresholds = {})` | Same rationale as F-1. |

### 1.3 Security Condition — Resolved

| Condition | Requirement | Implementation |
|-----------|-------------|----------------|
| **W-P1** | Rate limiter on power panel switch toggle calls (10 calls per 10s) | `_powerToggleLimiter = createRateLimiter(10, 10000)` — same factory as `_alarmPinLimiter` (3/60s) and `_irrigationLimiter` (5/10s). Wraps `_handleToggle()` calls in power panel renderer. Story 6. |

#### Story 3: Power Entity Partition, Classification & Grouping

**As a** power panel renderer, **I need** functions to partition entities into functional groups (switches, power sensors, energy sensors, voltage, current), classify devices into tiers (vue/plug/strip), group strip children under parents, and detect 240V pairs, **so that** the rendering stories have clean data structures to work with.

**Conditions addressed**: C-6

**File modified**: `src/lcars-homepage-card.js`

**Implementation**:

1. **`_partitionPowerEntities(entries)`** — Per Data C-6. Returns `{ switches, powerSensors, energySensors, voltageSensors, currentSensors, diagnostics }`. Filters out `disabled_by` and `hidden_by`. Code from Wesley addendum appendix.

2. **`_classifyPowerDevice(entries, device)`** — Returns `'vue'|'plug'|'strip-parent'|'strip-child'|null`. Logic from Geordi spec §7.2, with strip parent/child distinction via `via_device_id`. Note: strip parent detection uses `switchCount >= 4` OR model match.

3. **`_groupPowerStrips(powerDevices)`** — Groups strip children under their parent by `via_device_id`. Returns `{ strips: Map<parentId, { parent, children[] }>, standalone: Array }`. Code from Wesley addendum §3.2.

4. **`_detect240VPairs(circuits)`** — Matches L1/L2 circuit pairs using `L1L2_PATTERN` regex. Returns array with paired circuits merged. Code from Geordi spec §7.4.

5. **`_sortCircuits(circuits)`** — Power draw descending, then alphabetical for ties. Code from Wesley addendum §6.

6. **`_getPrimaryPower(group)`** — Extract primary power reading (W) from a device group's entries. Returns `number|null`.

7. **`_getPrimaryEnergy(group)`** — Extract primary energy reading (kWh today) from a device group's entries. Returns `number|null`.

8. **`_formatWatts(watts)`** / **`_formatEnergy(kwh)`** — Display formatting. Code from Wesley addendum §7.

**Acceptance criteria**:
- [ ] `_partitionPowerEntities` correctly buckets entries by device_class and domain
- [ ] `_classifyPowerDevice` returns `'vue'` for Emporia, `'plug'` for Kasa KP115, `'strip-parent'`/`'strip-child'` for HS300
- [ ] `_groupPowerStrips` nests 6 child outlets under HS300 parent
- [ ] `_detect240VPairs` merges "Dryer L1" + "Dryer L2" into single 240V entry with combined wattage
- [ ] `_detect240VPairs` leaves odd-count "pairs" unpaired
- [ ] `_sortCircuits` orders highest wattage first, alphabetical for ties
- [ ] `_formatWatts(4872)` → `'4,872 W'`, `_formatWatts(12500)` → `'12.5 kW'`
- [ ] `_formatEnergy(47.3)` → `'47.3 kWh'`

**Definition of Done**: Code complete, build succeeds, classification functions testable in isolation.

**Review gate**: Data (architecture — partition completeness, classification edge cases), Worf (security — L1L2 regex safety, entity filtering)

## 1. Mission Briefing

The monolith `lcars-homepage-card.js` has grown to **7,545 lines** — one class, 10 inline panel renderers, 3,634 lines of CSS, and every shared utility method inlined alongside domain-specific logic. This is unsustainable. It blocks v5.0 multi-dashboard architecture, makes individual panel maintenance hazardous (any CSS change risks collateral damage to all panels), and violates every principle of component isolation that Lit was designed to provide.

**The objective**: Decompose the monolith into **10 panel custom elements**, a **shared base class**, and a **thin orchestrator** — without changing a single pixel of rendered output. This is a structural refactor with zero visual regression.

**What we gain**:
- Each panel owns its shadow DOM, CSS, state, and lifecycle — isolated, testable, reusable
- Orchestrator drops from ~7,545 lines to ~2,200 lines (orchestration + domain renderers + shared state)
- CSS deduplication eliminates ~600 lines of repeated frame/panel chrome styles
- v5.0 multi-dashboard: same `<lcars-climate-panel>` on Habitat, Environmental, and Power dashboards
- Per-panel maintenance: modify alarm CSS without touching climate, battery, or any other panel

**What doesn't change**:
- Rendered output: pixel-identical before and after
- Bundle: single `lcars-dashboard.js`, +0.3% overhead from module boundaries
- Lit version: stays on LitElement v2
- HA integration: same `add_extra_js_url()`, same custom element registration pattern

### Risk R8 Detail — Animation CSS Cross-Boundary Issue

The orchestrator's animation CSS (lines 1801–1951) includes selectors like:
```css
.climate-panel[data-heat],
.climate-panel[data-cool] { animation: lcars-heartbeat 3s ease-in-out infinite; }
```

After extraction, `.climate-panel` is inside the climate panel's shadow DOM. The orchestrator's CSS cannot reach it. **These animation rules must move to the respective panel's CSS**, using the same selectors (they'll work within the panel's shadow root).

Similarly:
```css
.content-area-panel .lcars-device-panel { animation: lcars-cascade-in ... }
```
This animates panel entrance. After extraction, `<lcars-climate-panel>` is a custom element in the orchestrator's DOM, but `.lcars-device-panel` is inside its shadow DOM. The fix: add `:host { animation: lcars-cascade-in ... }` to the panel's CSS, triggered by a property or attribute.

**Mitigation**: Audit all animation selectors during cleanup (Phase 11). Move panel-entrance animations to panel `:host` CSS.

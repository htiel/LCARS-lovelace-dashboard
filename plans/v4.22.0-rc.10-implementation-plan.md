## Mission

Resolve Life Support clipping at the root by removing passive AQ monitors from the nested atmoscrubber substation path and splitting Life Support's internal environment partition into:

- Climate: nested thermostat panel
- Scrubber: active purifier entities with fan + AQ signals, still rendered by the environment panel
- Sensor Array: passive AQ monitors such as Awair, rendered inline inside Life Support
- Ambient: standalone temperature/humidity sensors

This plan explicitly does not change device-level panel routing. `classifyDevice()` and `isEnvironmentEntity()` remain responsible for routing both purifier devices and passive AQ-monitor devices to `PANEL_TYPE_ENVIRONMENT` at the device level. The split happens only inside Life Support.

## Root Cause Summary

The reopened bug is not just overflow styling. Life Support currently groups all environment entities into one nested `lcars-environment-panel`. That is correct for active air purifiers, but wrong for passive AQ monitors:

- passive sensors get rendered with a cylinder/controls metaphor they do not support
- nested full-width environment content inside Life Support creates the clipping path seen with Awair sparklines
- the current 3-group partition (`climate`, `environment`, `ambient`) cannot distinguish active treatment devices from read-only monitoring devices

The design-approved fix is to preserve device-level environment classification while adding a second-stage split inside Life Support.

## Scope

### In scope

- Add Life Support-only AQ predicates in entity utilities
- Replace the 3-group Life Support partition with a 4-group partition
- Add a new inline sensor-array rendering path inside Life Support
- Add matching Life Support styles for the sensor-array layout
- Update the atmoscrubber spec so sensor-only adaptation is deprecated in favor of the Life Support sensor array

### Out of scope

- No changes to `classifyDevice()`
- No changes to `lcars-environment-panel.js`
- No new standalone web component for sensor arrays
- No broader environment-device routing changes outside Life Support

## Risks And Mitigations

| Risk | Probability | Impact | Mitigation |
|---|---|---|---|
| Mixed-device rooms are split incorrectly because Life Support evaluates entries individually instead of by grouped device composition | Medium | High | Keep the split device-aware inside `_buildDeviceGroup()` or a nearby helper so the presence of one purifier fan classifies the whole environment device as scrubber-backed |
| Passive AQ sensors lose sparkline visibility after un-nesting | Medium | Medium | Reuse the existing Life Support sparkline tray and include AQ sensor entities in the same sparkline fetch path |
| The new config matrix regresses existing climate-only or atmos-only rooms | Medium | Medium | Preserve existing branches and validate each degradation mode after the partition rewrite |
| Sensor-array styles introduce new overflow or crowded mobile layouts | Medium | High | Add responsive grid collapse rules in the Life Support style file and visually validate narrow widths before cutting rc.10 |
| Spec drift returns later because atmoscrubber docs still imply sensor-only support | High | Medium | Update Section 8 in the same RC and call out the deprecation explicitly |

## Definition Of Done

- Life Support no longer renders passive AQ monitors inside a nested atmoscrubber substation.
- Purifier-backed devices still render through `lcars-environment-panel` unchanged.
- Passive AQ monitors render as an inline LCARS sensor array with no cylinder and no controls.
- The original clipping scenario for issue #44 is no longer reproducible in the mixed room layout.
- All five Life Support states render correctly: `full`, `atmos-only`, `climate-only`, `sensor-array-only`, and `sensors-only`.
- `classifyDevice()` behavior is unchanged.
- `isEnvironmentEntity()` remains available and unchanged for device-level routing.
- The frontend build passes.
- The atmoscrubber spec is reconciled with the shipped behavior.
- RC bookkeeping is complete for v4.22.0-rc.10 before release.

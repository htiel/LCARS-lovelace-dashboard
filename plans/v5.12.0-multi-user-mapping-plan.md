## Storage schema

`config/lcars-dashboard/configs/medical_profiles.yaml`:

```yaml
version: 1
respect_user_scoping: true     # spec §7.7 toggle, default true
profiles:
  - id: person.john_doe        # canonical HA person entity_id
    label: "John Doe"          # optional display override (defaults to person friendly_name)
    bindings:                  # binding keys this person owns
      - hae:leith              # HAE / Apple Health prefix bucket
      - withings:1a2b3c        # platform:config_entry_id
      - oura:7e8f9d
    entity_overrides:          # optional fine-grained adjustments
      include: []              # explicit entity_ids to attribute to this person
      exclude: []              # explicit entity_ids to exclude (even if binding matches)
```

Validation rules (Worf):
- `id` must match `^person\\.[a-z0-9_]+$`
- `bindings[*]` must match `^[a-z0-9_]+:[A-Za-z0-9_-]+$`
- `entity_overrides.{include,exclude}[*]` must be valid entity_ids
- File-size cap reuses `_JSON_MAX_BYTES` (256 KB); depth cap reuses `_check_depth` (max 20)

## WebSocket API

Two commands, both registered in `__init__.py` alongside the existing 37:

| Command | Auth | Payload | Returns |
|---|---|---|---|
| `lcars_dashboard/medical_profiles/get` | Any auth user | `{}` | `{ version, respect_user_scoping, profiles: [...] }` (or `{ version: 1, profiles: [] }` if file absent) |
| `lcars_dashboard/medical_profiles/set` | `@websocket_api.require_admin` | `{ data: <full mapping object> }` | `{ ok: true }` after atomic write |

`set` performs full validation (schema + size + depth), atomic write (`tempfile + os.replace`), and emits a `lcars_dashboard_medical_profiles_updated` bus event so other connected sessions can invalidate cache.

## Frontend changes

### Phase 1 — wiring (this beta)

1. **`lcars-medical-utils.js`**: new `getMedicalProfileMap(hass)` accessor that fetches the WS payload once per `hass.connection`, caches on a `WeakMap`, listens to `lcars_dashboard_medical_profiles_updated` for invalidation.
2. **`discoverProfiles(hass)`**:
   - Walk `hass.states` and classify medical entities exactly as today.
   - Compute `bindingKey` per entity using the same logic that today produces `profileKey`, but **expose it as a separate value** (not the bucket key).
   - If `getMedicalProfileMap(hass)` is non-empty: bucket entities into `person.*` buckets per the mapping; bindings not present in the map fall into a synthetic `unmapped:<bindingKey>` bucket so they surface to the Captain.
   - If the map is empty: behave exactly as today (HAE-prefix collapse).
3. **`lcars-medical-card.js`**: header label uses person friendly_name when bucket is `person.*`; otherwise current `fileIdFor()` chrome label is preserved.

### Phase 2 — editor UI (next beta, after Captain review)

Gear icon top-right of Medical card → `<lcars-medical-binding-editor>` modal:

- Lists all detected binding keys with sample entities count
- For each, dropdown `(unmapped) | person.alpha | person.beta | …`
- Add/edit `entity_overrides`
- Save → `medical_profiles/set` → close → cache invalidates

### Phase 3 — viewer masking (separate beta)

Spec §7.7 masking applied at render time in `lcars-medical-card.js`:
- Accessor `currentUserId(hass) = hass.user?.id`
- Accessor `isAdmin(hass) = hass.user?.is_admin`
- For each rendered tile/callout: if profile is `person.X`, `respect_user_scoping = true`, viewer is not the linked user, and viewer is not admin → render value glyph as `•••` (row chrome unchanged)
- Module-load warning if `respect_user_scoping = false`: `medical dashboard: per-user scoping disabled — vitals visible to all dashboard users`

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| Mapping file corrupt → all profiles break | `medical_profiles/get` returns `{ version: 1, profiles: [] }` on parse error; warning logged; UI shows "mapping unavailable, using auto-discovery" |
| Person `user_id` link missing in HA | Masking is opt-out via `respect_user_scoping`; UI editor surfaces a warning row when person has no `user_id` and admin attempts to enable masking |
| `discoverProfiles` cache stale after mapping change | Invalidate the `_discoverProfilesCache` `WeakMap` on every `medical_profiles/get` cache update |
| Performance: mapping fetch on every render | Single fetch per `hass.connection` lifetime; subsequent renders read the cached map synchronously |
| Spec §4.6 mentions person→profile link in UI; we don't have it yet | Phase 2 editor delivers it |

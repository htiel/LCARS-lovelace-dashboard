## Geordi La Forge — chrome + pixel pass (LEAD)

### Chrome parity grep gate (run before viewing images)

The two grep tests from `.github/agents/geordi.agent.md` pass against current source (post-fix). **Yet** the rendered Medical and Starship dashboards still show the pre-fix chrome — because the user's HA is serving the cached beta.1 bundle for those two dashboards. The grep gate is honest about source; what reaches the eye is the deployed bundle. **The protocol must therefore include a deploy-vs-source sanity check.**

### Image findings (S0)

- **`08-medical-top.png`** — sidebar filler is a SOLID PURPLE rectangle below the "BIOFUNCTION MONITOR" pill, with NO top-left rounded corner. Bottom-left elbow is also purple — matches accent but the filler should be neutral gray. Endcap right of the orange header bar shows only the `mdi:volume-high` button; `mdi:sort-variant` and `mdi:cog-outline` are absent. **Confirms LCARS-PARITY-medical-filler, LCARS-PARITY-medical-admin-chrome.**
- **`09-starship-top.png`** — same pattern in butterscotch. Sidebar filler below the "VESSEL STATUS" pill is a solid brown rectangle, sharp corner. Endcap mute-only. **Confirms LCARS-PARITY-starship-filler, LCARS-PARITY-starship-admin-chrome.**

### Image findings (S1 — clipping & alignment)

- **`04-tactical-top.png`** — the SHIELDS status indicator: the word "DISARMED" rendered as a sub-label *inside* the white status ring overflows the ring boundary on both ends, so the first and last characters disappear behind the stroke. Either the text needs to fit a smaller diameter, or the ring needs more clear-inside-area. Same pattern would presumably break "TRIGGERED" or "ARMED HOME" when those states activate. **`LCARS-CLIP-tactical-shields-ring`.**

### Image findings (positives, parity confirmed elsewhere)

- **`02-illumination-top.png`** — sidebar filler gray, all 3 endcap icons present, ALL DEVICES / LIGHTS / CIRCUITS filter pills render correctly. Active filter is gold; inactive are violet. Color separation between pill states is clean.

## Process retrospective (what the protocol learned)

### What the protocol caught successfully

| Bug from user's first-pass | Caught by | Evidence |
| --- | --- | --- |
| 1, 2 (Medical/Starship filler color) | Geordi pixel pass | S0-01, S0-03 |
| 6, 7 (Medical/Starship missing admin chrome) | Geordi pixel pass | S0-02, S0-04 |
| 3 (SHIELDS clipping) | Geordi clipping check | S1-01 |
| (Bug 4 — NETWORK HEALTH missing data) | Did NOT reproduce in this crawl; subspace `06-*` shows full network-health panel | — |
| (Bug 5 — ALL pill blue bleed) | Did NOT clearly reproduce; the ALL pill on Subspace is the orange active-state and other pills are sky-blue. May have been describing a hover state not captured here. |

### What the protocol *missed* on this dry run (process defects)

1. **Pre-flight deploy verification was insufficient.** I read `package.json` version (beta.2) and assumed parity with the running bundle. But the deployed bundle is mixed beta.1/beta.2 across dashboards. **Fix**: add a Phase-A step that visits one canonical dashboard, reads the footer text, compares to source `package.json`, and aborts if mismatched — or annotates the crawl-dir name with `-served-<deployed-version>`.
2. **Crawl skipped per-area Habitat drill-down.** Beta.1 directory has 20 per-area captures (21-40). This dry run only captured the homepage. **Fix**: the per-dashboard inventory in the protocol enumerates filters but doesn't enumerate area/sub-page recursion. Add an explicit Phase-A.4 sub-page recursion step (it's in the protocol prose but not in the inventory table). **STATUS: addressed in addendum below — 18 per-area captures added.**
3. **No modal / more-info captures.** Captain's protocol calls for "every modal open"; I did not click into any tile to capture a more-info popup. **Fix**: extend the per-dashboard loop with "click each card body, capture, close" — but bound it (e.g. one per row class) to avoid combinatoric blow-up.
4. **No persistent-state variations.** Tactical was only captured in DISARMED. ARMED HOME / NIGHT / TRIGGERED variants not exercised. **Fix**: the protocol lists these but the crawl loop didn't trigger arming. Acceptable for a non-destructive dry run; flag-and-skip is the right call as long as it's documented.
5. **`INDEX.md` was not generated.** Protocol requires one. **Fix**: append an INDEX-generation step at the end of Phase A — single Get-ChildItem pipe with descriptions.
6. **Bottom-scroll captures were skipped** because every dashboard happened to fit in one viewport (h=1179 == vh=1179). Protocol said "scroll until end" — script correctly detected single-viewport and skipped. No defect, but the script's behavior should be documented.

### What the protocol exposed that the bug list didn't

- **Bundle-version drift** (S0-05) is a genuinely new defect class. It implies HACS/HA caching is per-route, not per-bundle, which destroys the v=… cache-bust contract documented in user memory. Worth investigating: does HA serve `lcars-medical.js` vs `lcars-starship.js` as separate cacheable resources? If so, version-bumping `lcarsPkg.version` alone won't invalidate every route.
- **Cetacean empty state** (S1-02). Either expected (no entities) and should be silenced via dashboard hiding, or a real binding regression — but the previous beta.1 audit doc never raised it. Worth confirming with the captain whether aquatic systems are even configured on this HA.
- **Disconnected-device empty-tile noise** (S2-02) — a presentation defect that the previous audit didn't catch because nobody was specifically looking at the disconnected rows in `NETWORK HEALTH`.

### Net protocol verdict

Eight of the captain's bugs map to two source files and one deploy issue. The crawl + per-officer review correctly caught all the chrome-drift defects on the deployed bundle, the clipping defect, and surfaced three new defect classes (bundle drift, empty state, disconnected-tile noise) the previous content-only audit had missed.

The protocol works. Gaps in the *dry run* — modal captures, persistent-state variations, INDEX.md, deploy verification — should be tightened into the next revision of `.github/VISUAL-CRAWL-PROTOCOL.md` in the same commit that fixes any of the S0/S1 defects above.

### New defects surfaced by area drill-down

- **S1-05 Habitat sidebar/content desync** — clicking Office (idx 14) leaves the sidebar highlighting Game Room (idx 13) as the active gold pill. Either an event-handler race or the active-state computation lags the area-switch by one tick. Reproducible across the loop. Geordi to investigate.
- **S1-06 Master Bedroom MEDIA STANDBY** — confirms open bug 4X-63 from the backlog. The standby placeholder + LEFT/RIGHT 0% bars + WITHINGS offline tile take ~280px of vertical space for zero useful information when no media is playing. Should collapse to a single-line "STANDBY" indicator or hide entirely.
- **S2-03 Server Room IPC-MODEL adopt prompt** — an unadopted Unifi device should not surface in a normal-user view; the `ADOPT DEVICE` button is admin chrome bleeding into the area dashboard.
- **S2-04 Server Room BREAD CAM `ESTABLISHING LINK`** — either the camera entity is offline (in which case it should render the offline placeholder, not the link-establishing one) or the loading state is permanent. Needs a timeout-fallback.

### What this addendum proves about the protocol

The original Phase-A loop hit 9 dashboards × N filters but skipped per-area recursion on the only dashboard that has it (Habitat). The Captain caught the gap immediately on visual review. Within one extra crawl iteration we surfaced **two new S1 defects and two new S2 defects** that would have shipped untested. **The protocol revision must promote per-area recursion from "consider" to "required" on Habitat, and add a generic sub-route enumerator (URL hash watcher) for any dashboard that uses fragment-based area routing in the future.**
